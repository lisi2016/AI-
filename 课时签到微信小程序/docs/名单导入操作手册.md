## 0. 先记住这 4 句话

1. **先校验后落库、整批原子**：任何一行不通过，这一批**一行都不会写入**，界面提示「先校验后落库：任何一行不通过则整批不入库，并给出逐行错误报告（绝不静默丢弃脏数据）」。所以可以放心反复试。
2. **「白名单」≠「账号档案」**：白名单（`whitelist`）只决定**能不能绑定微信**；课表导入查的是**账号档案**（`users`）。这两张表是分开的（详见第 5 步）。
3. **顺序必须是**：基础数据（院系 / 教学班）→ 白名单 → **教师先绑定微信** → 课表 → 班干部 → 学生。
4. **导入成功才生成快照**；**只有教务处（`admin`）能回滚**，回滚是**整表覆盖**，不是「撤销本次改动」。

## 1. 五步总览

| 步骤 | 后台选项卡 | 写入的数据表 | 唯一键 / 重复策略 | 前置条件 | 能否跳过 |
| --- | --- | --- | --- | --- | --- |
| ① 基础数据 | **院系** / **教学班**（导入中心最左两个页签） | `depts.json`、`classes.json` | `院系ID` / `教学班ID`（留空则按名称定位已有行，存在即原地更新） | — | **不能** |
| ② 白名单 | 工号学号白名单 | `whitelist.json` | `工号/学号`（存在则覆盖更新） | 院系 / 教学班已先导入 | **不能**（所有角色） |
| ③ 课表 | 授课任务（课表） | `course_tasks.json` | **无唯一键，按行追加**（重复导入会翻倍） | 教师 `users` 档案 + 教学班 | 能（但教师端「我的课程」为空） |
| ④ 班干部 | 班干部授权 | `users.json` + `whitelist.json` + `class_cadres.json` | `(教学班, 用户)`（存在则覆盖职务/优先级） | 教学班 | 能（但课时确认可能无人可签） |
| ⑤ 学生名单 | 学生名单 | `students.json` | `(学号, 教学班)`（存在则覆盖姓名/状态） | 教学班 | 能（仅影响人数显示与缺勤匹配） |

系统内部类型顺序已经和这条业务顺序对齐：`IMPORT_TYPES = ['depts','classes','tasks','students','whitelist','cadres']`（后台页签顺序与之一致）。顺序本身只决定接口 `type` 的合法取值，但**你必须遵守的业务先后**就是它：先院系，再教学班，其余随后。

**最小可用清单**：① 院系教学班 + ② 白名单；教师绑定微信后可发起课时确认；③④⑤ 都是增强项。

## 2. 导入前的通用准备

### 2.1 文件格式硬要求

| 项 | 要求 | 说明 |
| --- | --- | --- |
| 格式 | **CSV**，逗号 `,` 分隔 | 不支持制表符、分号分隔；不支持 `.xlsx` 直接上传 |
| 编码 | **UTF-8**（Excel 请选「CSV UTF-8(逗号分隔)」） | 存成 GBK 会中文乱码，表头识别失败后**会退化成「按固定列顺序」解析**，报错会很难懂 |
| 大小 | 单文件 ≤ 5 MB，一次一个文件 | 上传字段名固定为 `file` |
| 表头 | 第一行必须是表头 | 没有表头也能解析，但**不推荐**（见 2.2） |
| 引号 | 字段内含逗号时用 `"…"` 包裹 | 双引号转义写 `""`；解析器忽略 `\r`、忽略 BOM、忽略空行 |
| 首尾空格 | 自动去除 | 表头与单元格都会 `trim`，且表头会去掉空格与 BOM |

### 2.2 表头容错与「静默降级」风险

解析器对表头是**宽容**的：只要识别出的表头数 ≥ 期望列数的一半，就按表头定位列；否则**退化成按固定列顺序取数**。

- 判断方法：调用预校验接口时看返回里的 `headerless` 字段（`true` = 已退化）。
- 各类型「期望列数」（表头识别数不足它的一半就会退化成按列顺序解析）：院系 4、教学班 6、课表 13、学生名单 3、白名单 5、班干部 5。
- 建议：**永远直接下载模板填写**，不要自己敲表头；表头顺序建议与模板一致。

### 2.3 权限与可见范围

- 导入接口角色白名单：`admin`（教务处）、`dept_admin`（院系管理员）。
- 导入历史：`dept_admin` **只能看到自己发起的导入任务**；`admin` 能看到全部。
- 回滚：仅 `admin`（教务处）。

### 2.4 名称匹配规则（很重要）

白名单、课表、学生、班干部这 4 类导入里，院系名、教学班名都是**先按全名精确匹配**，都匹配不到时**再做「包含」子串匹配**（`教学班名.indexOf(输入名) >= 0`）。**优先匹配 `active` 行**，归档行仍可被命中（不会因为归档就报「不存在」）。

- 例：输入 `护理3班` 能命中 `2025级护理3班`；输入 `护理` 也能命中。
- 风险：**简称可能命中错误的班级**（谁先命中算谁）。所以 CSV 里的院系名 / 教学班名**一律写全称**，与 `depts.json` / `classes.json` 里的 `name` 完全一致。
- 名称不一致的代价：该行报错 → **整批不入库**。
- **例外**：「院系」「教学班」这两个页签**自己不用**这套宽松匹配，那里的「上级院系 / 所属院系」只认**院系ID 精确**或**名称全等**（见 3.3.3）。

### 2.5 覆盖还是追加？

- 院系、教学班：也按唯一键**覆盖更新**（键 = `院系ID` / `教学班ID`；ID 留空时按**名称全等**定位已有行）。**导入绝不删除任何行**——「停用」请改状态为归档。
- 白名单、学生、班干部：**按唯一键覆盖更新**（同名键旧行被改写，不新增行）。
- 课表：**按行追加**（当前版本固定策略，暂不提供切换）。
- 导入前系统会对受影响表整表打快照，可用「回滚」整表还原。

## 3. 第 0 步：基础数据准备（院系 / 教学班）

### 3.1 为什么必须最先做

白名单、课表、学生、班干部这 4 类导入都会校验「院系 / 教学班是否存在」——它们必须先在系统里存在。

**院系 / 教学班现在可以直接在后台导入**：进入「数据」→「导入中心」，最左边两个页签就是「**院系**」与「**教学班**」，走与其他类型**完全相同**的链路（下载模板 → 预校验 → 确认导入 → 快照 / 回滚 / 导入历史）。

- 院系页签只写 `depts.json`，教学班页签只写 `classes.json`。
- 导入后**立即生效，不需要重启服务**。
- 手工改 JSON 仍然可行，但已降级为**兜底手段**（见 3.4）。

### 3.2 现网当前只有 2 个院系、2 个教学班

`depts.json`：

| id | name | code |
| --- | --- | --- |
| `D00000001` | 护理学院 | HL |
| `D00000002` | 药学院 | YX |

`classes.json`：

| id | name | grade | dept_id | advisor |
| --- | --- | --- | --- | --- |
| `C00000001` | 2025级护理3班 | 2025 | `D00000001` | 唐瑞明 |
| `C00000002` | 2025级药学1班 | 2025 | `D00000002` | 周慧敏 |

> 这是服务端的现状（种子数据）。真实院系 / 教学班以上表为准之前，请先用「导出当前数据（含 ID）」核对一次。

### 3.3 后台导入（推荐做法）

#### 3.3.1 「院系」页签

表头 **4 列**（顺序敏感，建议直接点「下载标准模板（CSV）」）：

| 列 | 必填 | 说明 |
| --- | --- | --- |
| 院系名称 | ✅ | 唯一键之一；与其他行或已有院系重名会被拒 |
| 院系代码 | | 如 `HL`，仅备注，不参与校验 |
| 上级院系 | | 留空 = 顶级院系；填**已存在的院系全称或院系ID**（不能填自己） |
| 院系ID | | **留空 = 按名称新增或更新**；填 ID = 按 ID 原地改名 / 改上级 |

模板样例（`template_depts.csv`）：

```csv
院系名称,院系代码,上级院系,院系ID
护理学院,HL,,
药学院,YX,,
```

- 新院系的 ID 由系统自动生成（`D` + 8 位序号），**不需要你填**。
- **院系没有「状态」列**：导入不会改已有院系的 `status`，新建的一律 `active`。要把某个院系置为归档 / 停用，只能改 JSON（见 3.4）。

#### 3.3.2 「教学班」页签

表头 **6 列**：

| 列 | 必填 | 说明 |
| --- | --- | --- |
| 教学班名称 | ✅ | 唯一键之一；建议写全称并带年级前缀，如 `2025级护理3班` |
| 年级 | | 留空时自动从名称里的「`2024级` / `2025级`」提取；提取不到就为空 |
| 所属院系 | ✅ | **必填**（新增和更新都要填）：已存在的院系全称或院系ID，**严格匹配、不支持简称** |
| 班主任 | | 仅备注，不参与任何校验 |
| 教学班ID | | 留空 = 按名称新增或更新；填 ID = 按 ID 原地改名 / 换院系 |
| 状态 | | `active`（启用）/ `archived`（归档）/ `leave`（休学）；也认中文 `启用` / `归档` / `休学`。留空 = 新建时 `active`、更新时**保持原值** |

模板样例（`template_classes.csv`）：

```csv
教学班名称,年级,所属院系,班主任,教学班ID,状态
2025级护理3班,2025,护理学院,唐瑞明,,active
2025级药学1班,2025,药学院,周慧敏,,active
```

- 新教学班的 ID 也由系统自动生成（`C` + 8 位序号）。
- 归档后的影响：后台的班级下拉默认**只列 `active` 的班**（历史数据仍在，不会丢）；而导入 / 绑定按名称匹配时仍能命中原班（同名前缀下会优先取 `active`）。

#### 3.3.3 与其它页签不同的三条规则（重要）

1. **严格匹配**：这两个页签里的「上级院系 / 所属院系」只认**院系ID 精确**或**名称全等**，**不做子串匹配**（2.4 里「简称也能命中」的宽松规则**不适用于这里**）。名称写法不一致 → 该行报错、整批不入库。
2. **导入从不删行**：改名、换院系、改状态都是**原地更新**；想让某个院系 / 教学班「消失」，请把状态改为归档（院系需要改 JSON）。
3. **同一份文件里不许重名**：同名出现两次会被拒，错误形如「与第 N 行重复（同一文件内院系「护理学院」出现多次），请合并为一行」。

还有一条**更新语义**必须知道：命中已有行时，除「状态」外的基本字段是**按 CSV 值整体覆盖**的——

- 院系更新：`院系名称`、`院系代码`、`上级院系` 全部覆盖，**代码留空会清空原代码、上级院系留空会把 `parent_id` 清成 null**。
- 教学班更新：`教学班名称`、`年级`、`所属院系`、`班主任` 全部覆盖，**班主任留空会清空原班主任**（年级留空时若名称里有「2025级」会自动补上）。

所以改数据时**不要只发一行孤零零的新值**，用下面的「导出当前数据（含 ID）」→ 改完整体回传最安全。

#### 3.3.4 改名 / 停用的标准做法

1. 切到「院系」或「教学班」页签 → 点「**导出当前数据（含 ID）**」（下载文件名 `export_depts.csv` / `export_classes.csv`，比模板多保留真实的 ID 列）。
2. 在导出的 CSV 里改名称 / 状态 / 院系归属，**ID 列原样保留不要动**。
3. 上传 → 预校验 → 确认导入。带 ID 的行**原地更新**，不会新增行，也不会影响文件里没出现的行。
4. 只想改一行时，也可以只上传改动的那一行（同样要带 ID 列）。

> 两个按钮别混：**「下载标准模板（CSV）」**是空白样式（新增用），**「导出当前数据（含 ID）」**是现网真实数据（改名 / 停用 / 查 ID 用）。

#### 3.3.5 落库、快照与回滚

- 导入成功会生成**导入前快照**，「导入历史」里可由**教务处（`admin`）**回滚；回滚是**整表覆盖**（见 8.2）。
- 权限与其他类型一致：`admin` / `dept_admin` 可导入，**仅 `admin` 可回滚**。
- `dept_admin` 只能看到自己发起的导入任务，`admin` 能看到全部。

### 3.4 手工改 JSON（兜底做法）

只在下面这些情形才需要动服务器文件：给**院系**置归档 / 停用（院系没有状态列）、批量修数据、导入链路本身出问题时。

#### 3.4.1 字段结构

```json
// backend/data/depts.json
[
  { "id": "D00000001", "name": "护理学院", "code": "HL",
    "parent_id": null, "status": "active", "created_at": "2026-09-27T13:27:44+08:00" }
]
```

```json
// backend/data/classes.json
[
  { "id": "C00000001", "name": "2025级护理3班", "grade": "2025",
    "dept_id": "D00000001", "advisor": "唐瑞明",
    "status": "active", "created_at": "2026-09-27T13:27:44+08:00" }
]
```

- `id`：院系 `D` + 8 位序号，教学班 `C` + 8 位序号；手工新增时**按现有最大值 +1**，不要重复（走导入的话系统会自动取 max+1，不用你算）。
- `status`：导入校验按名称匹配时**优先取 `active` 行**，但归档行**仍能被命中**——不会因为改成 `archived` 就报「院系 / 教学班不存在」。
- `advisor` 只是备注字段，不参与任何校验。
- `parent_id`：现网为 `null`（单层院系）；填了「上级院系」导入时会写成对方 `id`。

#### 3.4.2 操作步骤（服务器上执行）

1. 备份：
   ```bash
   cd /opt/apps/attendance/data
   cp depts.json depts.json.bak-$(date +%Y%m%d%H%M)
   cp classes.json classes.json.bak-$(date +%Y%m%d%H%M)
   ```
2. 编辑 `depts.json` / `classes.json`（保持 JSON 合法、逗号正确）。先把院系写好，教学班的 `dept_id` 必须指向已存在的院系 `id`。
3. 重启服务让数据重新载入：
   ```bash
   systemctl restart attendance
   systemctl is-active attendance
   ```
4. 验证：
   ```bash
   curl -s localhost:8081/api/v1/health
   curl -s localhost:8081/api/v1/classes      # 需带 token，或直接在后台「统计」页看班级下拉
   ```
5. 回到后台「导入中心」，在「院系」/「教学班」页签做一次**预校验**（或用「导出当前数据（含 ID）」核对），确认报错里不再出现「院系「…」不存在」「教学班「…」不存在」。

> 注意：**通过导入落库的数据不用重启**（导入会立即写盘并生效）；只有**手工改 JSON 文件**才需要重启。

### 3.5 连带影响：改名 / 归档之后会发生什么

改名（或换 `dept_id`）**不会**自动回填到已有引用。下面这些字段存的都是**旧的 ID**，改主数据不会动它们：

`whitelist.dept_id` / `whitelist.class_id`、`users.dept_id`、`class_cadres.class_id`、`students.class_id`、`class_courses.class_id`、`course_tasks.class_id`、`period_records.class_id`。

因为各类导入是拿 CSV 里的名称去**当前** `depts` / `classes` 里匹配的，所以：

- **改名前导入过、改名后还想再导入**的 CSV，必须把名称改成新名称再传（旧名称会报「不存在」）。
- 建议顺序：**先院系 → 再教学班 → 再白名单 / 课表 / 学生 / 班干部**；确需改名时，改完立刻用新名称重导受影响的名单。
- 要「停用但保留历史」：把教学班状态改为 `archived`（**不要删行**）。

### 3.6 已知缺口（后续建议）

- 院系仍然没有「状态」列 → 院系归档 / 停用只能改 JSON。
- 二级学院重组、班级更名会牵动多处已有引用（见 3.5），目前没有「批量迁移引用」的功能，只能改完名称后重导相关名单。
- 教学班的「班主任」只是备注，导入时不校验它是否真是系统里的教师。

## 4. 第 1 步：白名单（工号学号白名单）

**后台选项卡**：`工号学号白名单`

### 4.1 模板表头

```
工号/学号,姓名,角色,院系,教学班
```

- 表头别名（仅此一列有别名）：`工号/学号` 也可写成 `工号学号`、`工号`、`学号`、`编号`。
- 其余 4 列名称必须一致。

### 4.2 模板样例（可用「下载标准模板（CSV）」直接取到）

```csv
工号/学号,姓名,角色,院系,教学班
2010032,唐瑞明,teacher,护理学院,
2025030117,张一鸣,cadre,护理学院,2025级护理3班
```

### 4.3 角色取值（同义词可识别）

| 写入值 | 可识别的写法 |
| --- | --- |
| `teacher` | `teacher`、`教师`、`任课教师` |
| `cadre` | `cadre`、`班干部`、`学委`、`班长`、`副班长` |
| `dept_admin` | `dept_admin`、`院系管理员` |
| `admin` | `admin`、`教务处` |

无法识别时报：`角色「X」无法识别（teacher/cadre/dept_admin/admin）`。

### 4.4 列规则

| 列 | 必填 | 规则 |
| --- | --- | --- |
| 工号/学号 | ✅ | 去空格后按字符串处理；**建议 Excel 里把该列设为「文本」**，避免 12 位以上学号被转成科学计数法 |
| 姓名 | ✅ | 必须与教师/学生真实姓名一致；**课表导入会与该姓名做全等比对** |
| 角色 | ✅ | 见 4.3 |
| 院系 | 可空 | 填了就必须能在 `depts.json` 里匹配到，否则报 `院系「X」不存在` |
| 教学班 | 可空 | 填了就必须能匹配到；**`cadre`（班干部）必须填**，否则报 `班干部必须归属一个教学班` |

- 教师行：`教学班` 留空（例：`2010032,唐瑞明,teacher,护理学院,`）。
- 班干部行：`教学班` 必须填。
- `dept_admin` / `admin` 行建议填院系（院系管理员的可见范围由院系决定）；`admin` 可留空。

### 4.5 落库行为

- 只写 `whitelist.json`：键为 `工号/学号`，存在则覆盖 `姓名 / 角色 / 院系 / 教学班`，并把 `status` 重置为 `active`。
- **重新导入同一份白名单 = 让这些人重新变为「有效」**。要停用某人，请**不要**用导入，改为手工改 `whitelist.json`（`status` 改成非 `active`）并重启。
- 白名单行结构：`{ id, no, real_name, role, dept_id, class_id, status, created_at, updated_at }`；教师行 `class_id` 为 `null`。

### 4.6 两个必须知道的坑

**坑 1：白名单导入不会创建账号档案（`users`）。** 实测：导入白名单 2 行后，`whitelist` = 2 行，`users` = 0 行。账号档案只在两种情况下产生：

- 本人用微信完成绑定（`POST /api/v1/auth/bind` 成功时自动建档）；
- 导入「班干部授权」且该学号**尚无**档案时自动建档。

**坑 2：白名单导入会更新 `whitelist.dept_id`，但不会更新已绑定用户的 `users.dept_id`。** 实测：把 `2010032` 的院系从「护理学院」改成「药学院」再导入，`whitelist.dept_id` 变成 `D00000002`，而 `users.dept_id` 仍是 `D00000001`。而**统计学时口径、院系管理员权限看的是 `users.dept_id`**。

→ 结论：**批量调整院系时，导入白名单只完成一半**；已绑定的人还需要同步修 `users`（目前没有后台入口，只能改 `data/users.json` 并重启，或用解绑后重新绑定来重建档案）。

### 4.7 白名单没配好的时候，教师端会看到什么

绑定接口逐项校验白名单，失败统一返回 `40301`，常见原文：

| 报文 | 原因 |
| --- | --- |
| `工号/学号 X 不在白名单内，无法绑定` | 白名单没有这行，或该行 `status` 不是 `active` |
| `当前微信已绑定账号「…」，请联系教务处解绑` | 同一微信已绑定别的账号 |
| `该工号/学号已被其他微信绑定…` | 该工号/学号已被另一个微信占用（需走自助解绑或教务处解绑） |
| `班干部白名单缺少教学班信息，请联系教务处` | 角色为 `cadre` 但白名单该行 `教学班` 为空 |

## 5. 第 2 步：课表（授课任务）

**后台选项卡**：`授课任务（课表）`

> ⚠️ **这是最容易踩坑的一步**：它校验的是**账号档案 `users`**，不是白名单。白名单刚导完、老师还没绑微信时导入课表，会直接报「工号 X 不存在」。

### 5.1 模板表头（13 列，顺序敏感）

```
学期,工号,教师姓名,课程代码,课程名称,教学班,星期,节次,开始,结束,地点,周次,学时
```

### 5.2 模板样例

```csv
学期,工号,教师姓名,课程代码,课程名称,教学班,星期,节次,开始,结束,地点,周次,学时
2026-2027-1,2010032,唐瑞明,XXJS001,信息技术,2025级护理3班,周三,1-2,08:00,09:40,实训楼A302,1-18,2
```

### 5.3 列规则与默认值

| 列 | 必填 | 规则 / 默认值 |
| --- | --- | --- |
| 学期 | 可空 | 空则用服务端默认学期（`TERM` 环境变量，现网 `2026-2027-1`） |
| 工号 | ✅ | 必须在**账号档案**里存在「角色=teacher 且工号相同」的人（见 5.4） |
| 教师姓名 | ✅ | 必须与该档案的姓名**完全相等**，否则报「对应教师为「Y」，与「Z」不一致」 |
| 课程代码 | 可空 | 只做记录 |
| 课程名称 | ✅ | 后续班干部建「班级课程清单」时会用到同名课程 |
| 教学班 | ✅ | 必须匹配 `classes.json`，写全称 |
| 星期 | ✅ | `1`–`7` 或 `周一`…`周日`/`周天` |
| 节次 | ✅ | 形如 `1-2`（正则 `^\d+-\d+$`） |
| 开始 / 结束 | 可空 | 空则取 `SECTION_TIME[节次]`，查不到时用 `08:00` / `09:40` |
| 地点 | 可空 | 自由文本（≤60 字建议） |
| 周次 | 可空 | 空则默认 `1-18`；写法如 `1-16,18` |
| 学时 | 可空 | 空则默认 `2`；必须是正数 |

### 5.4 前置条件：教师必须先有账号档案

**实测（临时数据目录上跑真实导入代码）**：

1. 先导入白名单（含 `2010032 唐瑞明 teacher 护理学院`）→ `committed: true`，`whitelist=2`、`users=0`。
2. 紧接着导入上面的课表 → `committed: false`，逐行错误：`L2 工号 2010032 不存在（请先导入白名单或核对工号）`。
   - **提示语虽然写「请先导入白名单」，但白名单已经导入了。它真正查的是 `users` 档案。**
3. 手工补一条教师档案（等价于「该教师已完成微信绑定」）后，同一份课表 → `committed: true`。

**所以正确顺序是：**

- 路线 A（推荐）：导入白名单 → 通知全体教师用微信绑定一次 → 再导入课表。
- 路线 B（临时排课急用）：由运维在 `data/users.json` 里为教师补档案（至少要有 `role: 'teacher'`、`staff_no`、`real_name`、`dept_id`、`status: 'active'`），重启服务后再导课表。

### 5.5 重复导入会翻倍（按行追加）

**实测**：同一份课表导入两次，`course_tasks` 由 1 行变 2 行。课表导入**没有唯一键、不去重**。

- 补救：用「导入历史」里的**回滚**把该表恢复到导入前快照（教务处权限），或改单前先做快照备份。
- 后果提醒：重复的课表会让教师端「我的课程」出现同名重复任务；课时唯一性最终由**发起课时会话时的唯一键**（`教学班 + 上课日期 + 节次 + 实际授课人姓名`）守护，不会因为课表重复而重复计学时。

### 5.6 课表的作用范围（可跳过，但别误以为必须）

- 影响：教师端「我的课程 / 授课任务」列表、后台按学期下拉、发起课时时的**默认值回填**、以及「是否临时调整」的比对基准。
- 不影响：班干部可以在**没有课表**的情况下发起课时（系统允许「清单里没有这门课也允许发起」），课时信息的兜底优先级是「显式入参 > 班级课程清单 > 课表 > 默认值」。
- 若完全没有课表：教师端「我的课程」为空，但班干部出示动态码、教师扫码确认的闭环**照常可用**。

## 6. 第 3 步：班干部（班干部授权）

**后台选项卡**：`班干部授权`

### 6.1 模板表头

```
教学班,学号,姓名,职务,优先级
```

### 6.2 模板样例

```csv
教学班,学号,姓名,职务,优先级
2025级护理3班,2025030117,张一鸣,学委,1
```

### 6.3 列规则

| 列 | 必填 | 规则 / 默认值 |
| --- | --- | --- |
| 教学班 | ✅ | 必须匹配 `classes.json` |
| 学号 | ✅ | 学生的学号 |
| 姓名 | ✅ | 与学生姓名一致 |
| 职务 | ✅ | 自由文本（如「学委」「班长」），会写入该用户的 `duty` 字段 |
| 优先级 | 可空 | 空则默认 `1`；必须是 ≥1 的整数（用于同学班多人时的排序） |

### 6.4 落库行为（含一个坑）

| 情况 | 系统行为 |
| --- | --- |
| 该学号**已有**账号档案（按学号/工号/姓名+教学班匹配到 `users`） | 只写 `class_cadres`（键 `(教学班, 用户)`，覆盖 `职务/优先级/status`），并补 `users.duty`；**不会补写白名单** |
| 该学号**没有**账号档案 | 自动新建 `users`（角色 `cadre`）+ **自动补一条 `whitelist` 行**，再写 `class_cadres` |

**实测验证**：

- 已有档案的 `2025030109 刘欣` → 导入后 `whitelist` 行数 2 → 2（**没补**），`class_cadres` = 1。
- 没有档案的 `2025030102 王悦` → 导入后 `users` 3 行、`whitelist` 3 行，**白名单已自动补上**。

→ **坑**：如果某人**恰好已经有档案**（例如他已经绑定过、或早前被别的方式建过档），但白名单里没有他，那么导入班干部**不会**让他能重新绑定微信。此时必须先单独导入一次白名单。

### 6.5 班干部的作用

班干部（`cadre`）负责维护本班「班级课程清单」并出示动态码，是课时确认闭环的发起方；「课时确认将无人可签字」的提示即指此。教师在本流程中**永远不需要签字**。

## 7. 第 4 步：学生名单

**后台选项卡**：`学生名单`

### 7.1 模板表头

```
学号,姓名,教学班
```

### 7.2 模板样例

```csv
学号,姓名,教学班
2025030101,李思琪,2025级护理3班
```

### 7.3 落库行为与用途

- 唯一键 `(学号, 教学班)`，存在则覆盖 `姓名` 与 `status: active`。
- **本导入不会创建账号，也不会写入白名单**（学生名单 ≠ 白名单，学生本人无需登录）。
- 唯一的作用：① 后台按班级显示人数；② 教师登记缺勤时，把缺勤姓名原始文本与名单做匹配，结果标记 `matched` / `unmatched` / `ambiguous`。
- 匹配不上**不会阻断**任何操作：教师可以直接填自由文本缺勤姓名（长度上限由后台配置，默认 300）。

**结论：全校学生名单不是必须上传的**；要传就按教学班分批传，先保证教学班已存在。

## 8. 后台标准操作流程（每一步都一样）

> 页面流程：下载模板 → 拖拽或选择文件 → 预校验（逐行错误）→ 确认导入 → 导入历史（失败报告下载 / 回滚）

1. 打开「数据」→「导入中心」，选对应选项卡。共 **6 个页签**（顺序即建议的业务顺序）：**院系 → 教学班 → 授课任务（课表）→ 学生名单 → 工号学号白名单 → 班干部授权**。
2. 点「**下载标准模板（CSV）**」（或「查看模板列」弹窗核对表头；弹窗提示「CSV 表头（顺序敏感，建议直接下载模板填写）」）。「院系」「教学班」页签还多一个「**导出当前数据（含 ID）**」——改名 / 停用 / 查真实 ID 用它（见 3.3.4）。
3. 上传填好的 CSV → 自动进入**预校验**（提示「正在预校验（大文件可能需要数秒，请勿关闭页面）…」）。
4. 看预校验结果：
   - `全部行校验通过，可执行确认导入` → 点「**确认导入**」。
   - `存在校验不通过的行，整批不会入库（绝不静默丢弃脏数据）` → 点「**如何修正**」看指引，或「**重新预校验**」；此时「确认导入」按钮是灰色（`确认导入（校验未通过，已禁用）`）。
5. 点「确认导入」会弹确认框：「将把 **N** 行数据写入系统（类型：…）。导入前会自动保存受影响数据表的快照，必要时可在导入历史中回滚。」
6. 失败时弹窗提供「**下载失败报告**」（文件名 `import_errors_<jobId>.csv`，列为 `行号, 问题字段, 错误原因, 原始数据`，含**全部**错误行）。
7. 导入历史表格每行：类型 / 状态 / 行数 / 操作人 / 时间 / 失败报告「下载」/ 成功的任务显示「**回滚本次导入**」，已回滚的显示「已回滚」。

### 8.1 预校验返回字段（接口/排障用）

| 字段 | 含义 |
| --- | --- |
| `totalRows` | 数据行总数（不含表头） |
| `validRows` | 通过校验的行数 |
| `errorRows` | 错误行数 |
| `importableRows` | 可导入行数：**有错必为 0**（整批原子） |
| `valid` | `true` 才能确认导入 |
| `headerless` | `true` = 表头没识别出来，已按固定列顺序解析（重点排查项） |
| `errors[]` | `{ line, field, msg }`，最多返回 200 条；行号在有表头时从 2 开始（第 2 行） |
| `preview` | 表头 + 前 10 行预览，用于肉眼核对列错位 |

### 8.2 回滚规则

- 只有「导入成功」的任务能回滚，且必须有快照；已回滚的不能重复回滚。
- 回滚**用导入前快照整表覆盖**（`data/snapshots/snapshot_<jobId>.json`），会**连带丢掉该表在此之后的其它改动** → 界面已警告「回滚会覆盖该表当前内容，请确认该导入之后没有新的手工改动」。
- 各类型快照涉及的表：

  | 类型 | 快照 / 回滚涉及表 |
  | --- | --- |
  | `depts` | `depts` |
  | `classes` | `classes` |
  | `tasks` | `course_tasks` |
  | `students` | `students` |
  | `whitelist` | `whitelist` |
  | `cadres` | `users`、`whitelist`、`class_cadres` |

- 校验失败（整批不入库）的任务**没有快照、不能回滚**，也不需要——它本来就没写数据。

## 9. 常见报错对照表

> 「位置」= 这一行在 CSV 里的行号；有表头时第一行数据是第 2 行。

| 报错原文 | 触发条件 | 怎么处理 |
| --- | --- | --- |
| `第 N 列「工号/学号」不能为空` | 必填单元格为空，**或该列表头没被识别到**（列错位/表头写错） | 下载模板重填；核对表头是否被识别（看预校验 `headerless`、`preview`） |
| `第 N 列「姓名」不能为空` | 同上 | 同上 |
| `第 N 列「角色」不能为空` | 同上 | 同上 |
| `第 N 列「教学班」不能为空` | 教学班列缺失或为空（学生、班干部、课表都会出现） | 补齐教学班；课表/学生/班干部的教学班都是必填 |
| `角色「X」无法识别（teacher/cadre/dept_admin/admin）` | 角色写了别的词 | 用 4.3 同义词表里的写法 |
| `院系「X」不存在` | `depts.json` 里没有该名称（或名称写法不同） | 先做第 0 步；名称写全称 |
| `教学班「X」不存在` | `classes.json` 里没有该名称 | 先做第 0 步；名称写全称；注意简称子串匹配可能命中错班 |
| `第 N 列「院系名称」不能为空` | 「院系」页签里该行名称为空（或整列错位） | 补名称；确认表头被识别（看 8.1 `headerless`） |
| `第 N 列「教学班名称」不能为空` | 「教学班」页签里该行名称为空 | 同上 |
| `第 N 列「所属院系」不能为空` | 「教学班」页签里所属院系为空（**新增和更新都必须填**） | 填院系全称或院系ID |
| `院系ID「X」不存在（新增院系请留空该列，或改用「导出当前数据」获得正确 ID）` | 「院系」页签填了 ID 但 `depts.json` 里没有 | 新增就留空 ID；改名先「导出当前数据（含 ID）」 |
| `教学班ID「X」不存在（新增教学班请留空该列，或改用「导出当前数据」获得正确 ID）` | 同上，教学班页签 | 同上 |
| `院系名称「X」已被 D0000000N 使用（同一名称不能对应两个院系；改名请填该行的院系ID）` | 想改名但新名称已被别的院系占用，或同一文件里重名 | 换个不冲突的名称；改名必须带上该行的 ID |
| `教学班名称「X」已被 C0000000N 使用（同一名称不能对应两个教学班；改名请填该行的教学班ID）` | 同上，教学班页签 | 同上 |
| `上级院系「X」不存在（请先导入该院系，或留空表示顶级院系）` | 「院系」页签的上级院系填了系统里没有的名称/ID | 先导入上级院系，或留空（= 顶级院系） |
| `上级院系不能是自己（X）` | 某院系的「上级院系」填了自己 | 留空或改成真正的上级 |
| `所属院系「X」不存在（请先用「院系」页签导入院系，或改填院系ID）` | 「教学班」页签的所属院系填了系统里没有的名称/ID | 先导入院系；注意这里**只认全称或 ID，不认简称** |
| `状态「X」无法识别（应为 active/archived/leave，或 启用/归档/休学）` | 教学班状态写了别的词 | 用 `active`/`archived`/`leave` 或 `启用`/`归档`/`休学` |
| `与第 N 行重复（同一文件内院系「X」出现多次），请合并为一行` | 同一份 CSV 里同一个院系/教学班出现两次 | 合并为一行，只保留一条 |
| `班干部必须归属一个教学班` | 角色为 `cadre` 但教学班留空 | 给班干部行填教学班 |
| `星期「X」无法识别（应为 1-7 或 周一…周日）` | 星期写成 `星期三`、`Wed`、空白等 | 写 `3` 或 `周三` |
| `节次「X」格式应为 1-2` | 节次写成 `1`、`第1-2节`、`1~2` | 严格写 `起-止` 数字，如 `1-2`、`3-4` |
| `学时「X」应为正数` | 学时为空之外的非法值（`0`、`-2`、`两`） | 写正整数/小数（如 `2`、`1.5`） |
| `优先级「X」应为 ≥1 的整数` | 班干部优先级写了 `0`、`abc` | 留空（默认 1）或写 `1`、`2`… |
| `工号 X 不存在（请先导入白名单或核对工号）` | **课表**导入时 `users` 里没有「角色=teacher 且工号相同」的档案 | 见 5.4：先让教师完成微信绑定（或补 `users` 档案）；提示语里的「白名单」是误导 |
| `工号 X 对应教师为「Y」，与「Z」不一致` | 课表里「教师姓名」与该教师档案姓名不一致 | 以绑定时的白名单姓名为准，统一写法（不要有多余空格/曾用名） |
| `type 仅支持 depts\|classes\|tasks\|students\|whitelist\|cadres` | 调接口时 type 拼错 | 用这 6 个固定值 |
| `CSV 文件不能为空（multipart 字段名 file）` | 没选文件或上传字段名不对 | 界面正常上传即可；脚本调用时字段名必须是 `file` |
| `CSV 没有数据行` | 只有表头没有数据、或整份文件空行 | 补数据行；检查是不是导出成了空文件 |
| 预校验提示「存在校验不通过的行，整批不会入库」 | 有任意错误行 | 按 8.1 看 `errors[]` 逐行修 |
| `仅「导入成功」的任务可回滚，当前状态：x` | 对失败/已回滚任务点回滚 | 只有成功任务能回滚 |
| `该导入任务没有快照，无法回滚` | 该次导入没生成快照 | 只能靠备份恢复 |
| `导入快照文件已丢失，无法回滚` | `data/snapshots/` 下的快照被删 | 从服务器备份恢复 |
| `40301 工号/学号 X 不在白名单内，无法绑定` | 白名单缺行或该行非 `active` | 导入/修正白名单后再绑定 |
| `40301 当前微信已绑定账号「…」，请联系教务处解绑` | 该微信已绑定其他账号 | 教务处解绑或本人走自助解绑 |
| `40301 该工号/学号已被其他微信绑定…` | 该工号/学号被别的微信占用 | 解绑原微信后重绑 |
| `班干部白名单缺少教学班信息，请联系教务处` | `cadre` 白名单行缺教学班 | 重新导入该行白名单 |
| `50002 服务端未配置 WX_APPID / WX_APPSECRET…` | 服务端切到 `DEV_MODE=0` 但没有配微信密钥 | 配好 `WX_APPID`/`WX_APPSECRET` 再切；否则小程序登录会整体 502 |
| `40101 缺少 bindTicket…` | 非开发模式下未走 `wx.login` 直接调绑定 | 走小程序正常登录流程 |
| 打开「导入中心」报权限不足 | 登录账号不是 `admin` / `dept_admin` | 换教务处或院系管理员账号 |

## 10. 接口速查（脚本化 / 排障用）

所有接口都在 `/api/v1` 下，需带登录 token（`admin` / `dept_admin`）。

| 用途 | 方法 + 路径 |
| --- | --- |
| 下载模板（CSV） | `GET /api/v1/import/template?type=whitelist`（`sample=0` 可去掉示例行） |
| **导出当前数据（含 ID）**（仅院系 / 教学班） | `GET /api/v1/import/template?type=depts&data=1`（教学班用 `type=classes`） |
| 查看模板列（JSON，含示例行） | `GET /api/v1/import/template?type=whitelist&format=json&sample=1` |
| **预校验（dry-run，不落库）** | `POST /api/v1/import/precheck`（multipart，字段 `file`；也接受 `csv` / `content`） |
| 确认导入 | `POST /api/v1/import/{depts\|classes\|tasks\|students\|whitelist\|cadres}` |
| 导入历史 | `GET /api/v1/import/history?type=&status=&from=&to=&page=&pageSize=` |
| 单个导入任务详情 | `GET /api/v1/import/{jobId}` |
| 回滚（仅教务处） | `POST /api/v1/import/{jobId}/rollback` |

导入接口返回：`jobId / type / status / totalRows / successRows / failRows / committed / errors / errorReportUrl / canRollback / msg`（`errors` 最多 50 条，完整错误报告在任务里下载）。

`type` 取值固定为 `depts`、`classes`、`tasks`、`students`、`whitelist`、`cadres`（顺序即业务顺序：院系 → 教学班 → 课表 → 学生 → 白名单 → 班干部）。

- 模板接口默认 `type=tasks`、默认带示例行；`format=json` 时只返回 `{ type, headers, exported, totalRows }`，不下载文件。
- `data=1` 只对 `depts` / `classes` 有意义（导出真实数据并带 ID）；其余类型仍是模板。

```bash
# 预校验（不落库，先看有没有错行）
curl -s -X POST http://127.0.0.1:8081/api/v1/import/precheck \
  -H "Authorization: Bearer $TOKEN" \
  -F "type=whitelist" -F "file=@whitelist.csv"

# 确认导入
curl -s -X POST http://127.0.0.1:8081/api/v1/import/whitelist \
  -H "Authorization: Bearer $TOKEN" -F "file=@whitelist.csv"

# 院系 / 教学班：先导出当前数据（含 ID），改完名称再导回
curl -s "http://127.0.0.1:8081/api/v1/import/template?type=classes&data=1" \
  -H "Authorization: Bearer $TOKEN" -o export_classes.csv
curl -s -X POST http://127.0.0.1:8081/api/v1/import/classes \
  -H "Authorization: Bearer $TOKEN" -F "file=@export_classes.csv"
```

## 附录 A：本手册结论的验证方法（可复现）

手册中「实测」结论来自在**临时 `DATA_DIR`** 上直接调用后端导入代码（不接触任何真实数据）：

```js
process.env.DATA_DIR = '<临时目录>';           // 目录内预置 depts.json / classes.json
const io = require('<backend>/src/io.js');
const store = require('<backend>/src/store.js');
store.load();
const admin = { id: 'U_ADMIN', role: 'admin' };
io.importCsv(admin, 'whitelist', Buffer.from(csvText, 'utf8'), {});
```

| 验证项 | 结果 |
| --- | --- |
| 白名单导入后是否建账号档案 | `whitelist=2`、`users=0` → **不建** |
| 白名单已含工号时导课表 | `committed:false`，`工号 2010032 不存在（请先导入白名单或核对工号）` → 查的是 `users` |
| 补一条教师档案后导同一份课表 | `committed:true`，`course_tasks=1` |
| 同一份课表连导两次 | `course_tasks` 1 → 2 → **按行追加、不去重** |
| 白名单改院系后重导 | `whitelist.dept_id=D00000002`，`users.dept_id=D00000001` → **账号档案不同步** |
| 已有档案的学号导入班干部 | `whitelist` 2 → 2 → **不补白名单**，只写 `class_cadres` |
| 无档案的学号导入班干部 | `users`/`whitelist` 均 +1 → **自动建档并补白名单** |
| 学生 CSV 缺「教学班」列 | `第 2 列「教学班」不能为空`（表头模式，非静默跳过） |
| 预校验（合法数据） | `totalRows=2, importableRows=2, valid=true, errorRows=0, headerless=false` |

第 3 节的「院系 / 教学班」结论由脚本 `backend/tools/import-masterdata-test.js` 复现（**40 项断言全部通过**，同样只在临时 `DATA_DIR` 上跑，不碰真实数据）：

| 验证项 | 结果 |
| --- | --- |
| 类型顺序与表头 | `IMPORT_TYPES` = `depts,classes,tasks,students,whitelist,cadres`；两套表头与模板 CSV 逐字一致 |
| 院系新增 | `depts` 2 → 3，新 ID = `D00000003`（取现存最大序号 +1） |
| 院系按 ID 改名 / 改上级 | 原地更新，行数不变 |
| 教学班新增 / 更新 / 状态别名 | `归档` → `archived`，`启用` → `active` |
| 坏行整批拒绝 | 有任意错行时 `committed:false`，一行都不落库 |
| 同一文件内重名 | 报「与第 N 行重复（同一文件内…出现多次）」，整批拒绝 |
| 快照 + 回滚 | 回滚后 `depts` / `classes` 恢复导入前内容（整表覆盖） |
| 归档行仍可被匹配 | 命中 `archived` 的院系 / 教学班，不会报「不存在」 |
| 回归 | 原有 `precheck` 行为与审计计数不变 |
