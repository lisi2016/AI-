UI 方案对比 · 课堂课时确认与学时统计小程序

三套方案使用 同一页面、同一业务数据、同一功能范围 做公平比较，只改变视觉表达和布局：教师端首页（工作台，最高频任务页）+ 班干部端出示确认码页。 画布统一 375px，均显示状态栏、微信胶囊、顶部避让区、底部导航与底部安全区。 这是 HTML 预览，不是最终小程序——最终效果以微信开发者工具和安卓、iPhone 真机为准。

A · 微信原生稳妥方向

组件来源：WeUI + 原生组件 实现难度：低 落地风险：低 额外依赖：无

长相：白底、灰色分割线、小圆角（4px）、系统字体，和微信自带的界面几乎一样，教师上手零学习成本。 优点：实现最快、包体最小、不依赖任何第三方库，微信原生感最强，审核与兼容风险最低。 缺点：没有学校品牌感；学时数字只是普通文字，不突出；界面偏"工具表单"，教师快速扫一眼抓不到重点。 适合：想尽快上线试运行、先把流程跑通再做视觉的情况。

B · 品牌定制方向（TDesign MiniProgram）

组件来源：TDesign MiniProgram 实现难度：中 落地风险：中 额外依赖：npm 构建 + 包体增加

长相：TDesign 品牌蓝（#0052D9）、卡片化布局、12px 圆角、统一浅灰底色，数据用卡片承载，层次清晰。 优点：表单、列表、数据展示、日期选择、步骤条等组件齐全，后续加"补签审核""统计筛选"这类复杂表单最省事；品牌色可定制成学校色。 缺点：需要 npm 构建小程序，包体积增加，要跟随组件库版本升级；视觉仍是标准企业管理后台风格，辨识度一般。 适合：后续功能会持续扩展（审核流、规则配置、统计筛选）的情况。

C · 差异化可落地方向（原生 + 自定义 WXSS）

组件来源：原生组件 + 自研样式组件 实现难度：中高 落地风险：中 额外依赖：无第三方库

长相：蓝到深蓝渐变头部、本周学时用 38px 大数字顶到眼前、课程卡片带颜色左边条（已确认/待确认一眼分）、按钮用胶囊形。 优点：辨识度明显；教师最关心的"我这周多少学时"用最大字号呈现，扫一眼就有数；时间紧、光线差的走廊里也看得清。 缺点：渐变与阴影在安卓真机上表现需逐台检查；自定义组件多，后期维护成本高于 A/B；开发工作量比 A 多约 30%。 可落地性：所有效果均由 WXSS（linear-gradient、box-shadow、border-radius）与项目内本地图片实现，不使用 backdrop-filter、WebGL、SVG 动画或任何 Web 专有特性。

说明：三套方案的底部导航图标在 HTML 预览里用内联 SVG 示意，交付到小程序时必须替换为项目内本地 PNG（同时准备 iconPath 与 selectedIconPath）。 教师端与班干部端导航项不同，原生静态 tabBar 无法按身份切换，三套方案均采用自定义 tabBar（custom-tab-bar 组件），需额外处理选中态同步、页面切换与底部安全区。 三套方案均预留状态栏与胶囊避让，开发时用 wx.getMenuButtonBoundingClientRect() 动态计算，不硬编码位置。
