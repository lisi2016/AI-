# 小程序项目规划

## 产品

- 产品名称：课堂课时确认与学时统计（暂定名，正式名称以微信公众平台注册核定为准）
- 目标用户：任课教师、班干部（学委优先，请假时班长/副班长等）、教务处与院系管理员
- 要解决的问题：纸质课时确认表易丢失破损、难追溯；教师无法随时查看本人授课记录与累计学时；教务处统计滞后；补签代签漏签难监管；期末汇总重复录入易错
- 用户最重要的一次操作：教师课后发起本次课时确认 → 班干部核对并手写签名审核通过
- 核心业务规则：
  - 任课教师不能自签，签名必须由班干部完成（需求 5.2）
  - 班干部终审签字通过后才算"已确认"并计入正式学时
  - 确认时限为当天 24 点前，超时转补签流程
  - 同一教师 + 课程 + 教学班 + 节次只生成一条有效记录
  - 仅"已确认且未撤销"计入正式学时；补签计入但报表标注
  - 合班课程按授课任务统计，不按班级重复累加
  - 学时系数默认 1.0（理论/实践/实训系数由教务处配置，字段预留）
- 使用者和协作方式：教师提交申请 → 班干部核对签名 → 教务处查看统计与审核异常
- 数据保留和共享要求：课时记录、签字记录、操作日志建议长期保存不少于 5 年或按学校档案制度；每日增量备份、每周全量备份、备份加密（由后台实现，本期只定契约）
- 外部业务资料来源：`项目需求.md` V1.0（2026-09-27 编制，状态：草案待评审）
- 高影响字段确认状态：已确认（2026-09-27）
- 需求确认日期：2026-09-27

### 上线成功标准

1. 教师从"我的课表"到"提交待确认"不超过 3 步
2. 班干部从"收到待确认"到"签名提交"不超过 3 步
3. 一条记录走完"待确认 → 已确认"，教师端与管理员看板立即可见
4. 学时统计数字与明细逐条核对一致（准确率 100%）
5. 定位授权被拒绝时流程不中断，走降级留痕
6. 班干部动态码 60 秒后失效，截图复用失败
7. 静态检查通过（L1）、微信开发者工具编译通过（L2）
