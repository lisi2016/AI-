# 教务处 Web 管理后台 · 页面规格清单

- 版本：v0.1（草案）
- 日期：2026-09-27
- 定位：给后端开发方 / 信息中心的实现规格。本期**不写代码**，只定页面、字段、操作和验收点
- 接口依赖：`docs/miniapp/api-contract.md`
- 优先级：P0 = 教务处点名最急需（统计看板、导出、补签申诉审核、基础数据导入）；P1 = 支撑性功能

---

## 零、全局约定

| 项 | 约定 |
|---|---|
| 形态 | 响应式 Web，优先适配 1366×768 以上桌面，兼顾平板 |
| 浏览器 | Chrome / Edge 最近两个大版本；**不要求 IE** |
| 登录 | 账号密码（工号/学号）+ 图形验证码；若学校有统一认证，预留对接入口 |
| 导航 | 左侧一级菜单 + 顶部面包屑 |
| 表格 | 统一：筛选区 / 操作区 / 表格 / 分页 / 行操作 |
| 空态 | 每个列表页必须有空态文案与引导（如"还没有导入课表，去导入"） |
| 权限 | 菜单按角色显示，接口另行鉴权（**前端隐藏 ≠ 安全**） |
| 反馈 | 成功用顶部轻提示；失败用行内或模态，禁止只有 alert |

## 一、登录页 `/login` P0

- 元素：工号/学号、密码、验证码、登录按钮、忘记密码（联系管理员）
- 接口：`POST /auth/login`（Web 版走账号密码分支）
- 验收：连续 5 次失败锁定 15 分钟；密码不明文传输、不明文存日志

## 二、首页 · 学时统计看板 `/dashboard` P0 ★

教务处第一刚需，替代手工 Excel 汇总。

- **筛选区**：学期（默认当前）、日期范围、院系、课程、教师、状态
- **概览卡片**（4 个）：已确认学时 / 待确认条数 / 已过期条数 / 异常记录（过期+拒绝+待审）
- **院系学时排行**：横向条形图 + 表格（院系、已确认学时、完成率、教师数），点击行下钻到该院系教师明细
- **趋势图**：按周/月的已确认学时折线
- **教师学时排行 Top 20**：教师、院系、学时、课程数
- **快捷入口**：导出本页报表、去处理待审补签、去导入数据
- 接口：`GET /stats/overview`、`/stats/by-dept`、`/stats/trend`、`/stats/by-teacher`
- 验收：
  - 数字与「课时明细」逐条核对**一致**，这是硬指标（成功率 100%）
  - 补签记录在看板中单独标注，不与正常确认混计
  - 合班课程不重复累加
  - 无数据时显示空态与"先导入课表"引导

## 三、课时明细查询 `/records` P0 ★

- **筛选**：学期、日期范围、院系、教师（姓名/工号）、课程、教学班、状态（8 态可多选）、是否补签、是否现场指定签字人
- **表格列**：上课日期、节次、教师、工号、院系、课程、教学班、应计学时、状态、签字人、确认时间、是否补签
- **行操作**：查看详情（抽屉或新页）
- **详情内容**：
  - 授课信息（课程、班级、时间、地点、学时、缺勤、纪律、摘要）
  - **证据四项**：签名图（可放大、可下载）、确认时间、设备、动态码
  - 状态流转时间线（谁在什么时候做了什么）
  - 操作日志（该记录相关）
- **批量**：勾选后批量导出
- 接口：`GET /records`、`GET /records/{id}`、`GET /logs?targetId=`
- 验收：签名图必须能打开；状态与列表页一致

## 四、补签审核 `/makeup` P0 ★

- **Tab**：待我审核 / 已通过 / 已驳回 / 全部
- **列表列**：申请时间、教师、课程、教学班、上课日期、原状态、补签理由、证据附件数、操作
- **审核抽屉**：原记录详情 + 补签理由 + 证据附件 + 审批意见（驳回必填）
- **操作**：通过 / 驳回；通过后原记录置 `makeup`，计入正式学时但在报表标注
- **批量**：支持勾选批量通过（仅同院系）
- 接口：`GET /makeup`、`POST /makeup/{id}/approve`、`POST /makeup/{id}/reject`
- 验收：驳回必须填原因；审核结果写入操作日志；通过后统计看板数字立即变化

## 五、申诉处理 `/appeal` P0 ★

- 结构与补签审核一致，处理人为**教务处**（补签为院系管理员）
- 额外展示：原拒绝原因、教师申诉理由、双方证据
- **操作**：支持申诉（恢复为已确认）/ 维持原判；均需填写处理意见
- 接口：`POST /appeal/{id}/approve`、`POST /appeal/{id}/reject`
- 验收：同一记录申诉次数受控；处理结果回写原记录状态并留痕

## 六、数据导入中心 `/import` P0 ★

**没有这个，整个系统跑不起来**——课表、学生名单、白名单、班干部授权都从这里进。

- **四个 Tab**：授课任务（课表）/ 学生名单 / 工号学号白名单 / 班干部授权
- **每 Tab 结构**：
  1. 下载标准模板按钮（`GET /import/template?type=`）
  2. 拖拽或选择 Excel 上传
  3. **预校验结果预览**：总行数、可导入行数、错误行数，错误逐行列出（第几行、哪个字段、什么问题）
  4. 确认导入按钮（校验不通过时禁用）
  5. 导入历史列表（时间、操作人、类型、成功/失败行数、失败报告下载）
- **字段校验规则**：必填、格式、重复、外键存在性（如教师工号必须在白名单里、教学班必须存在）
- **重复策略**：提供"跳过 / 覆盖 / 报错停止"三选一，默认跳过
- 接口：`POST /import/tasks|students|whitelist|cadres`、`GET /import/{jobId}`
- 验收：
  - **绝不静默丢弃脏数据**，必须有逐行错误报告
  - 大文件（1 万行）异步处理，页面显示进度不卡死
  - 导入可回滚（至少保留最近一次导入前的快照）

## 七、报表导出中心 `/export` P0 ★

- **新建导出**：选择报表类型（课时明细 / 教师学时汇总 / 院系汇总 / 课程汇总）、筛选条件、格式（xlsx / csv）
- **任务列表**：创建时间、创建人、类型、状态（排队中/生成中/完成/失败）、下载按钮
- **下载**：链接有效期 1 小时，过期需重新生成
- 接口：`POST /export/records`、`POST /export/stats`、`GET /export/{jobId}`
- 固定表头（与 api-contract 第六节一致），不得因筛选条件变化而缺列
- 验收：导出数字与页面统计一致；补签单独列标注；下载行为记入操作日志

## 八、规则配置 `/config` P1

- 学时系数（理论 / 实践 / 实训，默认 1.0）
- 确认时限（默认当天 24:00）
- 动态码有效期（默认 60 秒）
- 补签审批层级（默认院系管理员）、申诉审批层级（默认教务处）
- 接口：`GET /config`、`PUT /config`
- 验收：改动立即生效并记日志；配置修改权限限教务处

## 九、用户与权限 `/users` P1

- **用户列表**：姓名、工号/学号、角色、院系、教学班、状态、绑定微信情况
- **班干部授权**（重点）：按教学班维护学委/班长/副班长的优先级与在岗状态（学委请假时置为 `leave`，系统自动顺位）
- **白名单维护**：单条新增 / 批量导入
- 验收：班干部请假状态变更后，新发起的记录自动改派签字人；已发起记录不受影响

## 十、操作日志 `/logs` P1

- 筛选：时间、操作人、角色、动作类型、目标对象
- 表格：时间、操作人、角色、动作、目标、IP、设备
- 支持导出
- 验收：日志不可编辑不可删除；哈希链校验结果可展示（可选页面）

## 十一、给实现方的建议（非强制）

1. **先做第六项导入和第七项导出**，教务处最先能感知价值的就是这两块
2. 看板数字和明细必须同源同一查询口径，否则一定会出现"两边对不上"的信任危机
3. 后台不要做成 SPA 巨石应用，按模块分页即可，降低维护门槛
4. **签名图建议单独对象存储**，数据库只存 URL 与哈希，避免库膨胀
5. 导出要做异步 + 限流，避免期末全校导出把服务打挂
6. 所有删除类操作一律软删除，物理删除需二次确认且仅管理员可用

## 十二、本期不做的部分

- 前端页面代码本身（本技能范围只到小程序）
- 数据大屏（FR-39，P2）
- 与教务系统、统一身份认证、人事系统的实时对接（改为 Excel 导入，接口契约已预留）
- 可靠电子签名（CA），当前签名仅为证据留痕
