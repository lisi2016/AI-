# 1 引言

## 1.1 编写目的

本文档用于明确“高职院校课堂课时确认与学时统计微信小程序”的建设目标、业务范围、用户角色、功能需求、数据需求、非功能需求、接口需求、验收标准和实施计划，作为后续原型设计、开发、测试、验收和运维的依据。

本文档适用于：

- 学校教务处、院系教学管理人员；

- 任课教师；

- 学生干部/学习委员；

- 信息中心、系统管理员；

- 项目开发、测试、实施和验收人员。

## 1.2 项目背景

目前学校一线教师上课后，主要采用纸质表格与学生确认课时。每位教师上完课，由学委或其他班干部签字，确认任课教师完成了本次授课。该方式存在以下问题：

1. 纸质表格易丢失、易破损、易涂改，历史追溯困难；

2. 教师无法随时查看本人每次授课记录和累计学时；

3. 教务处统计滞后，难以实时掌握全校教师授课学时；

4. 补签、代签、漏签、统计口径不一致等问题较难监管；

5. 期末汇总工作量大，数据重复录入，易出错；

6. 调课、停课、补课等场景缺乏统一线上记录。

   因此，有必要建设微信小程序及配套管理后台，实现课时确认、电子签字、实时统计、异常审核和报表导出。

## 1.3 术语与定义

|**术语**|**定义**|
|---|---|
|学时/课时|教学计量单位，1 学时原则上等于 1 课时，具体以教务处规则为准|
|教学班|由一门课程、一个或多个班级、一位任课教师组成的授课单元|
|学委/学生干部|负责课堂课时确认签字的学生代表|
|动态确认码|教师发起确认后，系统生成的短时有效二维码或数字口令|
|已确认学时|学生干部完成签字且记录未被撤销、拒绝或过期的学时|
|补签|超过规定时限后，通过审批流程补充确认的课时记录|
|申诉|教师或学生对课时记录有异议时发起的审核流程|
|教务课表|学校教务系统或教务处维护的课程、班级、教师、时间、地点安排|
|统一身份认证|学校用于校验教师工号、学生学号的认证系统|
|电子签名|学生干部在小程序内手写签名形成的确认证据，必要时可扩展可靠电子签名|

# 2 项目概述

## 2.1 建设目标

建设一套“可确认、可追溯、可统计、可审计”的课堂课时管理体系，实现：

1. 教师课后在线发起课时确认；

2. 学生干部在线核对并电子签字；

3. 教务处实时统计每位教师、每门课程、每个班级的已确认学时；

4. 教师可查看每次授课记录，并按时间段统计本人总学时；

5. 全流程留痕，支持补签、申诉、撤销、审核和导出；

6. 减少纸质流程，提高统计效率和数据准确性。

## 2.2 建设范围

本期建设包括：

- 微信小程序教师端；

- 微信小程序学生干部端；

- 教务处/院系 Web 管理后台；

- 后端服务、数据库、统计报表；

- 与学校统一身份认证、教务课表系统的对接预留；

- 动态确认码、电子签名、消息通知、操作日志；

- 数据导出、备份、审计和权限管理。

## 2.3 建设原则

1. **真实性**：确认过程须由学生干部参与，教师不能自签；

2. **可追溯**：每次确认保留时间、人员、设备、签名、动态码等证据；

3. **实时性**：教师确认后，教师端和教务处看板实时更新；

4. **规范性**：统计口径、学时规则、确认时限由教务处统一配置；

5. **安全性**：权限最小化，敏感数据加密，防止越权查询；

6. **易用性**：教师发起确认不超过 3 步，学生签字不超过 3 步；

7. **可扩展**：支持后续对接教务系统、人事系统、校园 APP。

## 2.4 目标用户

|**用户**|**使用端**|**主要诉求**|
|---|---|---|
|任课教师|微信小程序|发起确认、查看记录、统计本人学时|
|学生干部/学委|微信小程序|核对课程、电子签字、提出异议|
|教务处管理员|Web 管理后台|实时统计、审核、导出、配置规则|
|院系教学管理员|Web 管理后台|查看本院系数据、审核异常|
|系统管理员|Web 管理后台|用户、角色、权限、日志、接口管理|


## 2.5 成功标准

1. 教师可在课后 1 分钟内发起课时确认；

2. 学生干部可在 30 秒内完成扫码、核对、签名、提交；

3. 教务处可实时查看全校教师已确认学时；

4. 教师可按周、月、学期、自定义时间段统计本人学时；

5. 正式学时统计准确率达到 100%；

6. 纸质确认表使用量减少 90% 以上；

7. 全流程操作日志完整，可审计、可追溯。

# 3 总体业务流程

## 3.1 现状流程

1. 教师上课；

2. 课后教师持纸质表格与学生确认；

3. 学委或班干部签字；

4. 教师保存纸质表格；

5. 期末或月底汇总交教务处；

6. 教务处人工统计、复核、归档。

## 3.2 目标流程

1. 教务处导入学期课表、授课任务、班级、学生干部信息；

2. 教师微信登录并绑定工号；

3. 教师课后选择本次授课任务，核对课程、班级、时间、节次、应计学时；

4. 教师提交确认，系统生成动态二维码/确认码；

5. 学生干部扫码或输入确认码；

6. 系统校验学生干部身份、课程信息、确认时限；

7. 学生干部核对信息，手写电子签名，提交确认；

8. 系统生成课时确认记录，状态变为“已确认”；

9. 教师端即时可见，教务处统计实时更新；

10. 如学生有异议，可拒绝并填写原因；教师可申诉，教务处审核；

11. 教务处按时间段导出统计报表。

## 3.3 核心状态机

text

草稿 → 待确认 → 已确认              ├→ 已拒绝 → 申诉中 → 已补签 / 已撤销              ├→ 已过期 → 补签申请 → 已补签 / 已撤销              └→ 已撤销

状态说明：

|**状态**|**说明**|**是否计入正式学时**|
|---|---|---|
|草稿|教师暂存，未发起|否|
|待确认|已生成确认码，等待学生签字|否|
|已确认|学生干部已签字确认|是|
|已拒绝|学生干部拒绝确认并说明原因|否|
|已过期|超过确认时限未确认|否|
|申诉中|教师或学生对记录有异议|否|
|已补签|通过补签审批后确认|是，需标注补签|
|已撤销|经审核撤销的记录|否|

# 5 业务规则

1. **学时定义**：1 学时原则上等于 1 课时，理论、实践、实训系数由教务处配置。

2. **确认主体**：任课教师不能确认本人课时，必须由学生干部或指定学生确认。

3. **确认依据**：以教务课表、授课任务、实际上课时间、节次、班级、课程为依据。

4. **确认方式**：教师发起 → 系统生成动态二维码/口令 → 学生干部扫码或输入 → 核对信息 → 手写电子签名 → 提交。

5. **确认时限**：默认课后 24 小时内确认，可配置；超时需补签并说明原因。

6. **统计口径**：仅“已确认且未撤销”的记录计入正式学时；待确认、已拒绝、已过期、申诉中不计入。

7. **调停补课**：调课、停课、补课须关联原课表记录，避免重复统计。

8. **修改与撤销**：已确认记录不可直接修改；如需修改，须走撤销或申诉流程，保留原始日志。

9. **防重复**：同一教师、同一课程、同一班级、同一节次只能生成一条有效课时记录。

10. **数据留痕**：签名图片、确认时间、地点、设备、IP、动态码、操作日志须保存。

11. **签字有效性**：学生干部须为教务处或辅导员配置的有效身份；换人需重新授权。

12. **异常预警**：同一设备频繁签字、同一学生干部短时间大量签字、定位异常等应预警。

13. **数据归属**：跨月、跨学期课时按实际上课日期归属统计周期。

14. **合班授课**：合班课程按授课任务统计，不按班级重复累加教师学时。

15. **补签标注**：补签记录计入正式学时，但报表中应标注“补签”便于审核。

# 9 非功能需求

## 9.1 性能

1. 支持全校教师、学生干部同时使用；

2. 核心页面响应时间 ≤ 2 秒；

3. 统计查询响应时间 ≤ 3 秒；

4. 支持至少 500 并发用户，可扩展；

5. 报表导出 1 万条以内 ≤ 10 秒。

## 9.2 安全

1. 微信登录 + 工号/学号绑定；

2. 动态码短时有效，防截图复用；

3. 电子签名、时间、地点、设备多要素留痕；

4. 数据传输 HTTPS，敏感数据加密存储；

5. 权限最小化，防止越权查询；

6. 符合《个人信息保护法》《网络安全法》及学校隐私政策；

7. 关键操作二次确认；

8. 异常行为预警。

## 9.3 可用性

1. 教师发起确认不超过 3 步；

2. 学生干部确认不超过 3 步；

3. 页面简洁，适合中老年教师使用；

4. 支持大字体、清晰按钮、错误提示；

5. 关键操作有成功/失败反馈。

## 9.4 兼容性

1. 支持主流微信版本；

2. 支持 iOS、Android；

3. 管理后台支持 Chrome、Edge 等主流浏览器；

4. 适配不同屏幕尺寸。

## 9.5 可维护性

1. 模块化设计，便于对接教务系统；

2. 支持参数配置，减少硬编码；

3. 提供日志、监控、告警、备份机制；

4. 提供接口文档和运维手册。

## 9.6 合规与隐私

1. 仅收集必要信息；

2. 明示隐私政策；

3. 签字数据仅用于教学管理和审计；

4. 未经授权不得导出、外传；

5. 电子签名法律效力如需增强，可另行采用可靠电子签名服务。

## 14.2 统计口径建议

1. 正式学时 = 已确认 + 未撤销 + 未拒绝 + 未过期；

2. 补签学时计入正式学时，但报表标注“补签”；

3. 调课、补课关联原课表，不重复统计；

4. 跨月按实际上课日期归属；

5. 合班课程按授课任务统计，不按班级重复累加；

6. 实践、实训、理论系数由教务处配置；

7. 统计周期支持周、月、学期、学年、自定义。

## 14.3 签字确认证据要素

1. 确认人身份；

2. 手写电子签名；

3. 确认时间；

4. 确认地点；

5. 设备信息；

6. IP 地址；

7. 动态确认码；

8. 课程、班级、教师、节次、学时；

9. 操作日志。

## 14.4 待确认事项

1. 签字主体是仅学委，还是班干部均可？

2. 确认时限是课后 24 小时，还是当天？

3. 是否需要定位或教室扫码？

4. 是否需要全班学生参与确认？

5. 是否对接教务系统、统一身份认证？

6. 学时统计是否直接用于工作量核算？

7. 补签、申诉的审批层级如何设置？

8. 是否需要数据大屏？

# 15 结论

本项目的核心不是简单“电子签字”，而是建立一套**可确认、可追溯、可统计、可审计**的课堂课时管理体系。建议优先实现 P0 功能：教师发起、学生干部签字、课时记录、教师统计、教务处实时统计、权限与日志。后续再扩展全班签到、教务系统深度对接、智能异常预警等功能。
