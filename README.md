# 月度工作总结与计划生成系统（学校教研室版）

一个面向**学校各二级学院教研室**的月度总结与计划自动生成平台。各教研室教师通过网页提交自己的**本月工作总结**与**下月工作计划**，系统用**大模型**将全员内容归纳提炼为正式公文风格的**合并 Word 文档**（《XX教研室X月工作总结及X月工作计划》），并自动通过 **Agently Mail / SMTP** 发送到**学院指定邮箱**；每位教师还可获得一份**大模型润色后的个人优化文档**。

> 已实测部署于阿里云 Ubuntu 服务器，公网免备案，可直接用 `http://IP` 访问。

## 功能特性

| 能力 | 说明 |
|---|---|
| 🌐 网页提交 | 教师选教研室、总结月份，填总结+计划并提交；重复提交覆盖更新，刷新自动恢复（无需账号密码）|

| 🤖 大模型汇总 | 把全员内容**归纳提炼、按主题成段**，生成《总结+计划》**一份合并文档**（动宾小标题+成段叙述+落款）|
| 📧 自动发送 | 某教研室某月**全员提交后**自动生成合并文档并**发送到二级学院指定邮箱** |
| 👤 个人优化文档 | 每位成员提交后，大模型润色其个人总结+计划成规范文档，**自动发送**到学院邮箱，成员可下载 |

## 核心逻辑

1. **成员名单固定**：姓名只能在设置页维护的成员列表中选择。
2. **全员判定**：每次提交后判断"该教研室该月是否全部成员都已提交"。
3. **自动汇总**：全员到齐 → 大模型归纳生成**一份合并 Word** → 自动发送到**学院指定邮箱**（可抄送主任）。
4. **定时兜底**：每 60 秒检查当月是否"刚凑齐全员"（应对名单变动/重启场景）；发送失败 30 分钟后自动重试。
5. **个人文档**：每次提交后，异步生成该成员的个人优化文档并自动发送（同一成员+月份只自动发一次，修改时更新文档不重发）。

## 技术栈与架构

- **后端**：Node.js ≥ 18 + Express，纯 JSON 文件存储，**零数据库依赖**，单文件 `server.js`。
- **前端**：原生 HTML/CSS/JS（`public/`），无构建步骤。
- **Word 生成**：`docx` 库，A4 公文版式（宋体正文/黑体标题/1.5 倍行距/中文数字落款）。
- **邮件**：默认 **Agently Mail**（`agently-cli message +send`，自动确认、含附件）；备用 **SMTP**（`nodemailer`）。
- **大模型**：OpenAI 兼容 Chat Completions 接口（JSON 结构化输出），DeepSeek 默认。
- **自动汇总**：全员判定 + 实时触发 + 60 秒兜底 + 失败重试。

- Node.js ≥ 18（推荐 20+）；首次使用需联网安装依赖。

## 配置详解

在**系统设置**页（默认管理员密码 `admin123`，请尽快修改）：

1. **教研室与主任管理**：填写各教研室名称、**主任姓名/邮箱**（手动发送用）、**成员名单**（每行一个姓名，作为全员提交判定依据）。
2. **自动汇总设置**：
   - 启用自动汇总（全员提交后自动生成+发送）
   - **二级学院指定邮箱**（自动汇总/个人文档的收件人）
   - 可选"同时抄送教研室主任"
3. **邮件设置**：
   - **发送方式**：`腾讯 AI Agent 邮箱（推荐）` 或 `标准 SMTP`
   - SMTP 相关（host/端口/账号/授权码/发件人/邮件模板）在使用 SMTP 时填写
4. **大模型设置**：API 接口地址、API Key、模型、温度；可「测试连接」；未配置时自动降级为基础汇总模式。
5. **安全设置**：修改管理员密码。

## 邮件发送

| 方式 | 说明 | 配额 |
|---|---|---|
| **Agently Mail**（默认，推荐）| 腾讯 AI Agent 专属邮箱，走 `agently-cli` 命令行，为程序自动发信设计 | 日 50 封 / 时 200 / 分 10 |
| **SMTP**（备用）| 标准 SMTP+授权码，用 `nodemailer` 发送 | 取决于邮箱，个人 QQ 易触发风控 |

**Agently 接入**（服务器上执行一次）：
```bash
npm install -g @tencent-qqmail/agently-cli
agently-cli auth login   # 打开输出的链接，用 QQ 登录并授权
```
> `agently-cli` 的登录令牌绑定单台机器；换服务器部署时需在目标服务器重新授权一次。

## 大模型

- 默认对接 DeepSeek（`https://api.deepseek.com`，模型 `deepseek-chat` / `deepseek-v4-flash` 等），也兼容任意 OpenAI 风格接口。
- 提示词以"**你是一名教研室主任…**"身份撰写，要求：
  - **归纳提炼、同类合并、按主题成段**，严禁逐人罗列；
  - **不编造数据**：原始内容没有的数量用定性表述，没有的内容不写。
- 配置成功后，汇总/个人润色均为 `usedLlm=true` 的大模型质量。

## 部署到云服务器

> ⚠️ 国内部分云服务器**无法直接访问 Docker Hub / get.docker.com**（会连接重置）。本项目的云端部署因此采用**直接运行 Node** 的方式（更稳、无需 Docker）。

### 方式一：直接运行 Node（推荐，已实测）

```bash
# 1. 装 Node（Ubuntu 用 apt：nodejs v18+）
apt-get update && apt-get install -y nodejs npm

# 2. 上传项目到 /opt/mrgs（server.js、public/、package.json、package-lock.json、data/、reports/）
cd /opt/mrgs
npm install --registry=https://registry.npmmirror.com   # 国内镜像

# 3. 用 systemd 常驻（开机自启/崩溃重启）
#    /etc/systemd/system/mrgs.service
[Service]
WorkingDirectory=/opt/mrgs
ExecStart=/usr/bin/node server.js
Restart=always
Environment=NODE_ENV=production
Environment=PORT=80        # 云上常用 80，免配置防火墙
[Install]
WantedBy=multi-user.target

systemctl daemon-reload && systemctl enable --now mrgs
```

**公网访问**：云服务器**默认放行 22/80/443**，用 `PORT=80` 时直接 `http://公网IP` 访问，**免备案**（只绑域名才需备案）。若用 3081 等自定义端口，需在云控制台防火墙放行。

### 方式二：Docker（有 Docker Hub 网络时）

```bash
docker compose up -d --build
```
（`Dockerfile` / `docker-compose.yml` 已备好，数据卷挂载 `./data`、`./reports`。）

## 常见问题

- **汇总页月份只有一个？** 月份下拉固定提供最近 12 个月 + 有数据的月份，始终可选；选了无提交记录的月份会提示"暂无成员提交"。
- **收不到/发不出邮件？** 用 Agently 需服务器已装并授权 `agently-cli`；用 SMTP 需在设置页填授权码并测试；确认学院邮箱已填写。
- **自动汇总没触发？** 检查：自动汇总已启用、学院邮箱已填、该教研室是否全员提交（成员名单中的人都交了）。
- **汇总质量差？** 请确认大模型 API Key 已配置（未配置时为"基础模式"，仅按主题归类）。
- **端口被占用/无法访问？** 本地改 `PORT`；云端确认防火墙放行（80/443 默认放行）。
- **负责人/教师变动？** 在设置页改主任邮箱、成员名单即可，历史数据不受影响。
